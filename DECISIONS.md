# Architectural and Implementation Decisions

- Pinned `antd` to `5.29.3` and `react` to `18.3.1` because `@refinedev/antd@6.0.3` declares `peerDependencies.antd: "^5.23.0"` and is not peer-compatible with `antd@6.x`.
- Pinned `typescript` to `5.9.3` to satisfy `typescript-eslint@8.72.1` peer bounds (`<6.1.0`) under strict typechecking.
- Injected CSS custom properties at startup from `src/theme/tokens.ts` so stylesheet rules also avoid hardcoded color values outside `tokens.ts`.
- Added `updated_at` to `projects` maintained automatically via triggers on `projects`, `categories`, `items` and `releases` to power the Projects list "Last updated" column accurately.
- Standardized canonical `manifest_hash` JSON objects with fixed alphabetical keys (`category_name`, `category_position`, `file_name`, `file_size`, `kind`, `sha256`, `title`, `url`, `version_label`) and `COLLATE "C"` / Unicode code-point sorting so PostgreSQL `publish_release` and TypeScript `computeManifestHash` produce identical SHA-256 digests.
- Enforced category "delete when empty" via `ON DELETE RESTRICT` on `items.category_id`, keeping archived items linked to their category for audit history.
- Treated archived projects as read-only for categories, items and releases until unarchived by a project owner, and prevented removing or demoting the last project owner via trigger.
- Used `@electric-sql/pglite` (`pgcrypto`) in Vitest to run the exact `supabase/migrations/` and `supabase/seed.sql` files against a real PostgreSQL engine during `npm run test` without requiring a running Docker daemon.
- Kept an item's `kind` (`file` or `link`) immutable after creation while allowing file items to upload replacement files to new `{project_id}/{uuid}/{file_name}` paths, and used direct `XMLHttpRequest` to the Supabase Storage REST endpoint so browser uploads report byte-level progress.
- Migrated the application shell and all screens to `@refinedev/antd` (`ThemedLayout`, `ThemedTitle`, `List`, `Create`, `Show`, `Edit`, `PageHeader`, `useTable`, `@refinedev/antd/dist/reset.css`) and removed Ant Design's legacy `wireframe` mode in favor of crisp 6px radii and subtle surface elevation.
- Standardized typography across all screens on `Inter` (`400`/`500`/`600`/`700`), a compact engineering Ant Design v5 scale (`13px` base, `18`/`15`/`14`/`13`/`12` headings, `30px` control height), CSS `text-box: trim-both cap alphabetic` optical alignment for icons/badges/avatars, relative `rem` stylesheet sizing with `<meta name="text-scale" content="scale" />`, and monospace (`revlog-hash`) strictly reserved for cryptographic SHA-256 and `manifest_hash` digests.
- Extracted sidebar navigation into a declarative, section- and submenu-capable configuration (`src/components/navigationConfig.tsx`) rendered inside a scrollable (`overscroll-behavior: contain; scrollbar-gutter: stable`) `RevLogSider` shell with an active-project switcher header and pinned collapse footer so future feature modules can be added cleanly.
- Expanded the data and UI hierarchy to three levels (`projects` → `products` (`'hardware' | 'software' | 'mixed'`) → `categories` (modules) → `items`) with shared project-level RBAC (`project_members`), safe automatic migration/backfill of single-product v1 projects, and dual-level immutable SHA-256 releases (`releases` per product plus `project_releases` + `project_release_products` bundling published product releases into a system baseline via `publish_project_release`).
- Adopted a Supabase Studio-inspired header-first navigation shell (`src/components/AppLayout.tsx`, `src/components/navigationConfig.tsx`): `/projects` and `/projects/new` render without a left sidebar as a clean project-selection card grid, a full-width top context bar (`RevLog / Project ⌄ / Product ⌄ / Section`) provides searchable project and product switcher popovers that preserve sub-routes, and the collapsible left sidebar renders only once a project is selected, scoping its menu items to the active project or active product.
- Stored BOM/PnP check runs (`public.bom_pnp_check_runs`) as append-only immutable JSONB snapshots attached to product releases (`releases`), enforced by PostgreSQL triggers and RLS so new runs can only be recorded on active draft releases and stored results remain permanently frozen once a release is published.
- Implemented deterministic KiCad, Altium and custom-mapped delimited CSV/POS parsing in plain TypeScript with automated column detection, code-point deterministic finding sorting, and interactive column mapping override support.
- Adopted a Flat Project Menu + In-Page Horizontal Tabs navigation architecture: the left sidebar is permanently visible across all routes and dedicated strictly to project-level functions (Projects, Overview, Releases, BOM & PnP, Settings) with zero product dropdowns in the sidebar, while product context is decoupled into clean in-page horizontal tabs ([ All Products ] [ Sensor Board ] [ Gateway Firmware ] [ + New Product ]) above the page content that preserve sub-routes when switching tabs.
- Implemented deterministic release comparison (`src/lib/releaseCompare.ts`, `src/pages/compare/ComparePage.tsx`) operating strictly on immutable `release_items`, `bom_pnp_check_runs`, and `project_release_products` snapshots: categorizes item additions, removals, and modifications with cryptographic SHA-256 and URL diff highlighting, matches BOM components by reference designator using natural alphanumeric sort ordering (`C1` < `C2` < `C10`), and compares bundled product versions and manifest hashes for system-level project releases.
- Built on-demand release packaging and manifest engine (`src/lib/releasePackage.ts`, `fflate`): compiles all release snapshot files and `manifest.json` (version, date, publisher, canonical manifest hash, per-file SHA-256 and relative paths) directly into in-memory ZIP archives without persistent bucket storage, aborting package generation if computed release item hashes do not match the published database `manifest_hash`.
- Implemented expiring release share links (`supabase/migrations/20261108000002_release_share_links_and_audit_logs.sql`, `src/lib/shareToken.ts`, `src/pages/share/PublicSharePage.tsx`): generates 256-bit CSPRNG random tokens storing strictly SHA-256 digests in PostgreSQL, grants public anonymous read-only access to release snapshots and files via security definer RPCs and storage policies while enforcing expiration and revocation guards, and logs all link creation and revocation events to an append-only `public.audit_logs` table.
- Implemented release completeness checklist (`supabase/migrations/20261108000003_release_checklist_rules.sql`, `src/lib/completeness.ts`, `src/pages/projects/settings.tsx`, `src/pages/releases/wizard.tsx`): persists per-project required artifact rules (`release_checklist_rules`) with category matching and case-insensitive keyword/pattern evaluation; RLS allows members to manage warning-level rules while restricting creation and escalation of `'blocking'` rules strictly to project owners (`public.project_role = 'owner'`); the release wizard Review and Confirm steps evaluate selected release items against configured checklist rules, surfacing missing items with visual badges and blocking publishing whenever blocking rules remain unsatisfied.
- Implemented release approval workflow and second-person review engine (`supabase/migrations/20261108000004_release_approval_workflow.sql`): added optional `projects.require_release_approval` boolean setting; expanded `releases.status` to `('draft', 'in_review', 'approved', 'published')` with PostgreSQL check constraint `releases_published_fields_check` guaranteeing approval timestamps, submitter, and approver fields; strictly enforced the second-person rule via security definer RPCs (`submit_release_for_review`, `approve_release`, `reject_release`, `cancel_release_review`, `publish_release`) blocking self-approval by the release author or submitter, locking release item mutations while under review or approved, and recording all review events in `public.audit_logs`.
- Adopted `@tracespace/core` (`^5.0.0-alpha.0`) and `fflate` for client-side Gerber RS-274X, Excellon drill file, and CAM ZIP archive parsing, layer stackup extraction, and SVG rendering (`src/lib/gerber.ts`, `src/components/gerber/GerberViewerModal.tsx`): processes PCB layers entirely in-browser with zoom/pan controls, layer visibility toggles, top/bottom composite board renders, and XSS sanitization (`src/lib/svgSanitizer.ts`) without external server processing or unconstrained binary zip extraction.
- Implemented deterministic PnP component overlay and cross-referencing domain engine (`src/lib/pnpOverlay.ts`): provides footprint dimension estimation for passive chips (01005 to 2512), transistors, diodes, and IC packages (SOIC, TSSOP, MSOP, QFP, QFN, BGA, DIP) with explicit name-embedded millimeter dimension fallback; maps Gerber Cartesian coordinate space to SVG viewBox with Y-axis inversion and Tracespace bottom board horizontal mirroring (`2*minX + width - x`); handles bidirectional case-insensitive BOM designator matching across single and multi-reference rows; and standardizes PnP overlay color styling via design tokens in `src/theme/tokens.ts`.
- Integrated interactive PnP component overlay and bidirectional BOM linking into Gerber viewer modal (`src/components/gerber/GerberViewerModal.tsx`, `src/pages/releases/show.tsx`, `src/pages/bom-pnp/BomPnpPage.tsx`): aligns SVG overlay directly over top/bottom Gerber composites, supports side toggles (All/Top/Bottom), search filtering, component click-to-BOM inspection, and BOM row selection with multi-component highlighting and canvas auto-centering.
- Adopted Three.js (`three` ^0.187.0) for in-browser client-side 3D model visualization (`src/components/three/ThreeViewer.tsx`, `src/components/three/Model3DViewerModal.tsx`, `src/pages/board/BoardViewerPage.tsx`, `src/pages/releases/show.tsx`): directly supports binary glTF (`.glb`), JSON glTF (`.gltf`), and binary/ASCII Stereolithography (`.stl`) files with OrbitControls, directional and hemisphere lighting, wireframe toggling, ground grid alignment, bounding-box auto-framing, and interactive polygon/vertex dimension inspection. Evaluated client-side STEP (`.step`, `.stp`) ISO 10303-21 CAD solid tessellation via WebAssembly (`opencascade.js` ~30MB-50MB gzipped; `occt-import-js` ~3.5MB WASM binary with multithreading / SharedArrayBuffer COOP/COEP header requirements and 5-30s CPU lockup on complex assemblies). Due to severe bundle weight and performance constraints, client-side STEP parsing was rejected in favor of pre-exporting lightweight GLB or STL meshes during CAD/CI release automation, while preserving raw STEP files for download as primary mechanical CAD release artifacts.
- Implemented inline PDF and schematic preview without downloading (`src/lib/pdf.ts`, `src/components/pdf/PdfViewer.tsx`, `src/components/pdf/PdfViewerModal.tsx`, `src/pages/board/BoardViewerPage.tsx`, `src/pages/releases/show.tsx`, `src/pages/share/PublicSharePage.tsx`, `src/pages/items/ItemDrawer.tsx`): utilizes browser-native hardware-accelerated PDF rendering via Blob URLs (`URL.createObjectURL` with mime `application/pdf`) and embedded `<object>` / `<iframe>` layers with PDF open parameters (`#view=FitH&toolbar=1`). This achieves zero extra worker bundle overhead while rendering complex multi-sheet ECAD schematics and datasheets with crisp vector lines, native text selection, search, and page bookmarks. Extended the viewer with interactive zoom scaling (50% to 200%), 90-degree step rotation (vital for landscape A3/A4 schematics), fallback actions, and seamless integration across release files, public shared releases, the item drawer, and the Board Viewer with local external PDF drag-and-drop support.
